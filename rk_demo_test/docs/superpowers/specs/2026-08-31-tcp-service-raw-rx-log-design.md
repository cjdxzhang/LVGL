# tcp_service 原始接收日志设计

## 目标

为 `tcp_service` 增加 TCP 原始接收日志，确认 APP 实际发送的命令和 TCP 分包、粘包情况，为“界面状态变化但未下发 MCU 命令”的问题提供边界证据。

## 实现范围

- 在 `recv()` 返回正数后、累加 `client->rx_len` 和调用帧解析前记录本次接收数据。
- 日志包含客户端 IPv4 地址、客户端端口、本次接收字节数和原始数据。
- 原始数据严格使用 `recv()` 返回长度输出，不依赖字符串结尾，避免越界读取。
- 使用现有 `APP_LOG_USER` 日志设施，模块名使用 `TCP_SERVICE`。
- 不改变 TCP 帧格式、缓冲区处理、JSON 解析、响应以及 MCU 命令分发行为。

## 异常与安全边界

- `recv()` 返回零或负数时保持现有断连处理，不打印数据日志。
- 日志只覆盖单次 `recv()` 数据，因此能够直接观察半帧、粘连帧和无效前缀。
- 接收缓冲区单次最大长度受现有 `TCP_SERVICE_RX_BUFFER_SIZE` 限制；日志按明确长度打印，不把网络数据当作以 NUL 结尾的字符串。

## 验证

- 静态检查日志位置位于成功接收之后、缓冲区长度累加之前。
- 编译验证目标模块：`make lvgl_demo-dirclean && make lvgl_demo-rebuild`。
- 现场连接 TCP 客户端后确认日志包含客户端地址、端口、长度和 `@@JSON_BEGIN@@...@@JSON_END@@` 原始内容。
